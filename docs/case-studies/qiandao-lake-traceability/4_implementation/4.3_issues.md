## 问题 1：养殖模式枚举值未对齐

### 现象

测试发现保水渔业和 RAS 的数据查询结果不正确。

### 根因

PRD 中的养殖模式描述为「湖泊天然有机」，代码中枚举值为 `LAKE_NATURAL`，但技术方案中定义为 `WATER_CONSERVATION`，两处不一致。

### 发现方式

- [x] 单元测试
- [ ] 集成测试
- [ ] 人工发现

### 处理过程

```markdown
AI 产出 → Code Review 发现问题 → 提交 TL 确认 → 修复枚举值 → 重新测试
```

### 决策点

- 是否修改 PRD？
  - 建议：❌ 保持 PRD 描述，修改代码枚举值
  - 理由：PRD 已有正式评审，不宜频繁变更
  - 结论：✅ TL 同意

### 经验沉淀

更新 `memory/engineering.md`：
```markdown
## 枚举值同步规范
- 所有枚举值必须在代码、PRD、技术方案中保持一致
- 建议在详细设计阶段建立枚举表，发给业务方确认
```

## 问题 2：链上核验超时

### 现象

C 端溯源查询响应时间超过 10 秒，超出非功能需求中的 3 秒要求。

### 根因

链上核验调用蚂蚁链 API，由于网络延迟不稳定，平均耗时 5-8 秒。

### 发现方式

- [ ] 单元测试
- [x] 集成测试 / 性能测试
- [ ] 人工发现

### 处理过程

```markdown
性能测试发现 → AI 建议降级方案 → 技术评审确认 → 实施降级逻辑 → 验证
```

### 决策点

- 是否接受性能降级？
  - 建议：✅ 实施降级策略
  - 方案：链核验超时后返回「暂不展示链上核验」，不影响溯源链展示
  - 结论：✅ TL 同意

### 技术实现

```java
public TraceVerifyResult verifyOnChain(String traceCode) {
    try {
        // 超时 2 秒
        Response response = chainClient.verify(traceCode, 2, TimeUnit.SECONDS);
        return ResponseMapper.map(response);
    } catch (TimeoutException e) {
        log.warn("链上核验超时，返回降级结果");
        return TraceVerifyResult.degraded("暂不展示链上核验");
    }
}
```

### 经验沉淀

更新 `memory/decisions.md`：
```markdown
## 链核验降级决策
- 背景：链上核验不稳定，超出性能要求
- 决策：实施降级策略，超时返回提示
- 状态：已采纳
- 验证方式：性能测试验证
```

## 问题 3：与蚂蚁数科接口不兼容

### 现象

对接蚂蚁数科流通系统时，发现接口返回的数据格式与预期不一致。

### 根因

- 预期：JSON 格式
- 实际：XML 格式，且字段名不同

### 发现方式

- [ ] 单元测试
- [ ] 集成测试
- [x] 联调测试

### 处理过程

```markdown
联调发现问题 → AI 建议适配层方案 → 与蚂蚁数科沟通确认 → 实施适配层 → 重新联调
```

### 决策点

- 是修改适配层还是要求对方改接口？
  - 建议：✅ 修改适配层
  - 理由：对方接口已稳定，不宜要求变更
  - 结论：✅ 架构师同意

### 技术实现

```java
@Component
public class AntDigitalAdapter implements ExternalApiAdapter {
    
    @Override
    public ExternalData fetchCirculationData(String batchNo) {
        String xmlResponse = httpClient.get(circulationApi, batchNo);
        // XML 转 JSON
        JsonNode node = objectMapper.readTree(xmlResponse);
        return mapToStandardFormat(node);
    }
    
    private ExternalData mapToStandardFormat(JsonNode node) {
        return ExternalData.builder()
                . logisticsStatus(node.path("status").asText())
                . warehouse(node.path("warehouseName").asText())
                . build();
    }
}
```

### 经验沉淀

更新 `memory/decisions.md`：
```markdown
## 外部接口适配规范
- 背景：外部系统接口格式不可控
- 决策：实现适配层，隔离外部变更
- 状态：已采纳
```

## 经验总结

1. **枚举值同步**：详细设计阶段应建立枚举表，发给业务方确认
2. **降级策略**：依赖外部系统的核心功能，应设计降级方案
3. **适配层**：外部接口应通过适配层隔离，避免直接耦合
4. **测试覆盖**：联调测试不能省略，发现问题比修复成本高

---

> 📌 **经验**：
> 1. 踩坑是必然的，关键是建立经验沉淀机制
> 2. 决策应记录在 memory 中，便于后续追溯
> 3. 红旗机制帮助避免重大问题，但小问题仍需通过测试发现
