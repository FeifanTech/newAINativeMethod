# 4.2 代码生成

> 本节展示开发阶段的代码生成过程。
> 
> 使用 Skill: `development-principles` + `code-standards`

---

## 阶段流转

```
Sprint 1 启动
    ↓
开发任务执行
    ↓
Skill: development-principles + code-standards
    ↓
Code Review
    ↓
Human Gate: 合并到主分支
```

---

## 触发检查

AI 在开发过程中自动加载相关 Skill：

### 开发原则 (development-principles)

```
触发条件：用户提到写代码、开发、实施
执行原则：
  - 遵循核心原则：小步交付、质量门禁、可追溯、协作一致
  - 红灯清单：未经 Code Review 不可合并
```

### 代码规范 (code-standards)

```
触发条件：用户提到代码规范、Code Review、写代码
执行原则：
  - 遵循通用原则：可读优先、单一职责、错误处理、可测试
  - 产出：符合规范的代码 + Code Review 结论
```

## 开发过程示例

### 示例：批次创建 API

#### 需求描述

```
实现批次创建 API：
- 输入：养殖批次信息（养殖模式、数量、投放时间等）
- 处理：创建批次记录，生成溯源码
- 输出：批次ID、溯源码
```

#### AI 生成的代码

```java
// Controller
@RestController
@RequestMapping("/api/batch")
@RequiredArgsConstructor
public class BatchController {
    
    private final BatchService batchService;
    
    @PostMapping
    public ResponseEntity<BatchCreateResponse> createBatch(
            @Valid @RequestBody BatchCreateRequest request) {
        BatchCreateResponse response = batchService.createBatch(request);
        return ResponseEntity.ok(response);
    }
}

// Service
@Service
@RequiredArgsConstructor
@Slf4j
public class BatchService {
    
    private final BatchRepository batchRepository;
    private final TraceCodeGenerator codeGenerator;
    
    @Transactional(rollbackFor = Exception.class)
    public BatchCreateResponse createBatch(BatchCreateRequest request) {
        // 参数校验
        validateRequest(request);
        
        // 创建批次
        Batch batch = Batch.builder()
                .batchNo(generateBatchNo())
                .cultureMode(request.getCultureMode())  // 保水渔业 / RAS
                .quantity(request.getQuantity())
                .投放时间(request.getStockingTime())
                .build();
        
        batchRepository.save(batch);
        
        // 生成溯源码
        String traceCode = codeGenerator.generate(batch.getId());
        
        batch.setTraceCode(traceCode);
        batchRepository.save(batch);
        
        log.info("批次创建成功: batchId={}, traceCode={}", batch.getId(), traceCode);
        
        return BatchCreateResponse.builder()
                .batchId(batch.getId())
                .traceCode(traceCode)
                .build();
    }
    
    private void validateRequest(BatchCreateRequest request) {
        if (request.getQuantity() <= 0) {
            throw new BusinessException("数量必须大于0");
        }
        if (request.getCultureMode() == null) {
            throw new BusinessException("养殖模式不能为空");
        }
    }
}
```

## Code Review 检查

### AI 自检（使用 code-standards）

| 检查项 | 结论 | 说明 |
|--------|------|------|
| 命名与约定 | ✅ 满足 | 符合项目命名规范 |
| 单一职责 | ✅ 满足 | Controller 和 Service 分离 |
| 异常处理 | ✅ 满足 | 有参数校验和 BusinessException |
| 日志 | ✅ 满足 | 有操作日志 |
| 安全 | ✅ 满足 | 参数校验防止注入 |

### Human Code Review

| 审查人 | 问题 | 结论 |
|--------|------|------|
| 同事A | 缺少批次号生成规则 | ✅ 已修改 |
| 同事B | 事务注解位置正确 | ✅ 通过 |
| TL | 溯源码生成应异步，不阻塞主流程 | ⚠️ 需优化 |

> 📌 **经验**：
> 1. AI 生成的代码通常符合规范，但业务逻辑细节需要人工确认
> 2. Code Review 是必须的，AI 自检不能替代人工审查
> 3. 复杂逻辑（如溯源码生成）应与业务方确认规则
