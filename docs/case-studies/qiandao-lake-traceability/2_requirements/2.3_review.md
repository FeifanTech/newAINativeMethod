# 2.3 审核与反馈

> 本节展示 PRD 审核过程，包括业务方反馈和 Human Gate 决策。

---

## 审核流程

```
AI PRD 草稿 (v0.1)
    ↓
业务方评审 + 技术评审
    ↓
Human Gate: 产品负责人确认
    ↓
PRD 定稿 (v0.4)
```

---

## 第一轮反馈（业务方）

### 问题清单

| # | 反馈人 | 问题描述 | 优先级 |
|---|--------|----------|--------|
| 1 | 业务方 | 「湖里自然放养」描述不准确，应该是「保水渔业」，是科学投放+自然生长的模式 | 高 |
| 2 | 业务方 | 需要明确「单尾追溯」和「批次追溯」的区别，两种模式都要支持 | 高 |
| 3 | 业务方 | 遗漏了「认证与标签」功能，有机认证、地理标志需要数字化绑定 | 中 |
| 4 | 业务方 | 消费者扫码除了看溯源，还想展示「鱼的一生」时间轴，增加体验感 | 中 |
| 5 | 业务方 | 技术选型已经确定用蚂蚁链，请在背景中明确 | 中 |

### 采纳情况

| # | 是否采纳 | 处理方式 |
|---|----------|----------|
| 1 | ✅ 采纳 | 修改为「保水渔业（千岛湖天然有机）」 |
| 2 | ✅ 采纳 | 增加「单尾追溯与批次追溯并行」说明 |
| 3 | ✅ 采纳 | 补充「认证与标签」功能模块 |
| 4 | ✅ 采纳 | 在溯源查询中增加「鱼的一生」时间轴 |
| 5 | ✅ 采纳 | 明确技术选型为蚂蚁链 |

## 第二轮反馈（技术评审）

### 技术可行性问题

| # | 反馈人 | 问题描述 | 解决方案 |
|---|--------|----------|----------|
| 1 | 技术负责人 | 与蚂蚁数科对接方式需要明确，是 API 还是数据同步？ | 明确采用 API 对接，获取流通数据 |
| 2 | 技术负责人 | 链上核验失败时如何降级？ | 降级为「暂不展示链上核验」，溯源链仍可展示 |
| 3 | 技术负责人 | 批量上链的性能瓶颈？ | 引入队列机制，异步上链 |

### 采纳情况

| # | 是否采纳 | 处理方式 |
|---|----------|----------|
| 1 | ✅ 采纳 | 在PRD中明确「与蚂蚁数科流通系统对接」 |
| 2 | ✅ 采纳 | 补充「降级策略」说明 |
| 3 | ✅ 采纳 | 在非功能需求中增加「批量上链队列+重试」 |

---

## Human Gate 决策

### 决策要点

产品负责人（Human Gate）在审核后确认：

1. **范围确认** ✅
   - 覆盖养殖、加工、检测环节
   - 流通环节仅做数据对接，不重复建设

2. **优先级确认** ✅
   - P0：核心闭环功能（登记→上链→溯源查询）
   - P1：增值功能（认证、监管大屏）

3. **风险确认** ⚠️
   - 蚂蚁数科对接进度需提前跟进
   - 链上核验降级方案需技术验证

### 决策结果

```
✅ 通过，允许进入技术方案阶段
```

---

## 产出

PRD 从 v0.1 更新为 v0.4，包含：
- 完整的背景与目标（含技术选型）
- 详细的用户与场景（双模式）
- 展开的功能列表（含优先级）
- 完整的非功能需求
- 可衡量的成功指标

---

> 📌 **经验**：
> 1. 审核过程需要业务方和技术方共同参与，避免需求与实现脱节
> 2. Human Gate 是必须的，AI 不能自己决定「可以进入下一阶段」
> 3. 反馈应当结构化记录，便于追踪和版本管理
