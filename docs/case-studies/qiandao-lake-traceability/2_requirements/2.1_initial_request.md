# 2.1 原始需求

> 本节展示用户（产品负责人/业务方）向 AI 提出的原始需求。

---

## 需求提出

**场景**：业务方（商达公用）提出溯源系统建设需求，技术团队需要转化为产品方案。

---

### 用户原始需求（口语化表达）

```
我们想做一个千岛湖的鱼产品溯源系统。

千岛湖有两个养殖模式：
1. 保水渔业，就是湖里自然放养，不喂饲料那种
2. RAS工厂化养殖，用循环水

需要能追溯鱼从苗种到餐桌的全过程，包括养殖、捕捞、加工、检测这些环节。
流通环节（就是运出去之后）已经有蚂蚁数科的系统在做了，我们这边只需要对接他们的数据。

政府需要监管大屏能看到所有养殖主体、批次、检测数据。
消费者买了鱼之后扫码能看到鱼的一生，还能验证这个数据是不是真的上链了。

技术方面要用蚂蚁链来做存证，数据标准要跟浙食链兼容，以后还要能对接全国平台。

预算和具体功能优先级你们来定，我先了解下整体方案和大概工作量。
```

---

## AI 理解与分析

基于原始需求，AI 应用 `product-design-principles` Skill 进行理解：

### 触发检查

- [x] 用户提到「溯源系统」「PRD」「需求」
- [x] 涉及产品设计，需要明确目标用户与场景

### 需求要素提取

| 要素 | 提取结果 |
|------|----------|
| **目标用户** | 政府监管方、商达/养殖企业、加工/检测主体、消费者 |
| **核心场景** | 养殖数据上链、消费者扫码溯源、监管大屏 |
| **关键约束** | 蚂蚁链、浙食链兼容、对接蚂蚁数科 |
| **技术选型** | 蚂蚁链（已明确） |

### 红旗检查

| 红旗项 | 状态 | 说明 |
|--------|------|------|
| 无PRD进入实现 | ✅ 未触发 | 处于需求阶段 |
| 验收标准不可测 | ⚠️ 待明确 | 需在 PRD 中量化 |
| 关键假设未记录 | ⚠️ 待确认 | 需确认与蚂蚁数科对接方式 |

---

## 转化为结构化需求

AI 将口语化需求转化为结构化的需求描述：

### 业务范围

1. **种源与投放** - 苗种登记、生态容量模型
2. **养殖与捕捞** - 保水渔业 + RAS 双模式
3. **加工与检测** - 批次管理、检测报告上链
4. **流通对接** - 读取蚂蚁数科数据（不重复建设）
5. **溯源查询** - C端扫码 + 链上核验
6. **政府监管** - 大屏、报表、抽检预警

### 待确认事项

1. 与蚂蚁数科对接的具体接口和数据格式
2. 溯源码生成规则（按批次还是按单尾）
3. 上链频率要求（实时还是批量）
4. 预算范围和上线时间要求

---

## 产出

输出「需求理解确认」文档，发给业务方确认后进入 PRD 编写阶段。

---

> 📌 **经验**：口语化需求往往缺少边界定义，AI 需要主动识别并列出「待确认事项」，避免后续返工。
