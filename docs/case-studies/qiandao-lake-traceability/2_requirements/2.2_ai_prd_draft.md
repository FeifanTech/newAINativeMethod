# 2.2 AI PRD 草稿

> 本节展示 AI 基于原始需求生成的 PRD 草稿。
> 
> 使用 Skill: `product-design-principles`

---

## 触发检查

AI 根据用户需求，自动加载 `product-design-principles` Skill：

```
触发条件：用户提到写 PRD、需求评审、功能设计
执行原则：
  - 遵循核心原则：用户与场景先行、目标可衡量、优先级清晰、闭环与反馈、一致性
  - 使用产出模板：背景、目标、用户与场景、功能列表、非功能需求、成功指标
```

---

## AI 产出：PRD 草稿（v0.1）

```markdown
# 千岛湖全鱼品溯源平台 · 产品方案（PRD）

> 版本：v0.1（草稿）
> 生成时间：2024-XX-XX

---

## 一、背景与目标

### 1.1 背景

- **客户**：商达公用集团（千岛湖智慧鱼谷）
- **项目**：千岛湖全鱼品溯源体系建设
- **核心诉求**：建设可验真、不可篡改、多方共治的全鱼品溯源体系

### 1.2 产品目标

| 目标 | 衡量方式 |
|------|----------|
| 全链路可追溯 | 各环节登记上链，支持单尾/批次追溯 |
| 数据不可篡改 | 关键操作与凭证经蚂蚁链存证 |
| 消费者可验真 | 扫码查看溯源链 + 链上核验 |

---

## 二、目标用户与典型场景

### 2.1 目标用户

| 用户角色 | 描述 | 核心诉求 |
|----------|------|----------|
| 政府监管方 | 农业农村/渔业主管部门 | 主体监管、检测监控、违规预警 |
| 养殖企业 | 商达及合作养殖户 | 数据上链、品牌溢价 |
| 消费者 | 购买千岛湖鱼产品的 C 端 | 溯源查询、验真 |

### 2.2 典型场景

- 保水渔业：鱼苗投放 → 自然生长 → 捕捞 → 吊水净化 → 流通
- RAS养殖：种苗引进 → 循环水养殖 → 加工 → 流通

---

## 三、功能列表

### 3.1 核心功能

| 模块 | 功能点 | 优先级 |
|------|--------|--------|
| 主体管理 | 养殖企业、合作社注册 | P0 |
| 养殖登记 | 保水渔业/RAS双模式数据采集 | P0 |
| 批次管理 | 批次号生成、溯源码绑定 | P0 |
| 加工检测 | 加工批次、检测报告上链 | P0 |
| 流通对接 | 读取蚂蚁数科流通数据 | P0 |
| 溯源查询 | C端扫码、链上核验 | P0 |
| 监管大屏 | 政府监管报表 | P1 |
| 认证管理 | 有机/地理标志证书绑定 | P1 |

---

## 四、非功能需求

| 类型 | 需求 |
|------|------|
| 性能 | 溯源查询响应 ≤ 3s |
| 可用性 | 业务系统 ≥ 99% |
| 安全 | HTTPS、接口鉴权 |
| 合规 | 数据脱敏、日志可审计 |

---

## 五、成功指标

- [ ] 覆盖两种养殖模式
- [ ] 消费者扫码可查看完整溯源链
- [ ] 链上数据可验真
- [ ] 政府监管大屏上线

---

> ⚠️ **待确认**：具体功能细节、优先级调整、预算范围
```

---

## 草稿评估

### 红旗检查

| 红旗项 | 状态 | 说明 |
|--------|------|------|
| 在未形成 PRD/范围的情况下进入详细设计 | ✅ 已避免 | 先写 PRD 草稿 |
| 验收标准不可测 | ⚠️ 部分达标 | 部分目标可衡量，部分待细化 |
| 关键假设未记录 | ⚠️ 待补充 | 与蚂蚁数科对接方式未明确 |

### 检查清单

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 背景与目标 | ✅ 包含 | 有背景描述和产品目标 |
| 用户与场景 | ✅ 包含 | 有目标用户和典型场景 |
| 功能与优先级 | ⚠️ 待细化 | 粒度较粗，需要展开 |
| 非功能需求 | ✅ 包含 | 有基本非功能需求 |
| 成功指标 | ⚠️ 部分可测 | 需要更量化 |

## 下一步

1. 将草稿发给业务方确认
2. 根据反馈补充细节
3. 明确与蚂蚁数科的对接方式
4. 细化功能优先级

---

> 📌 **经验**：AI 生成的 PRD 草稿通常粒度较粗，需要业务方反馈后补充细节。AI 的价值在于提供结构化框架，避免遗漏核心要素。
