# 遗留项目架构基线快照模板

> 用于遗留项目接入初期，快速沉淀“当前仍然影响开发与 AI 判断的架构事实”。目标不是产出完整技术方案，而是在低成本下给团队和 AI 一个可靠的系统基线。

## 使用原则

- 只记录**当前仍然有效**的事实，不追求补齐全部历史。
- 优先记录**会影响开发判断**的边界、约束和风险。
- 控制在 2 到 5 页；若内容过长，说明你已经在写完整方案，而不是基线快照。
- 每条结论尽量能落到代码目录、部署单元、外部系统或可验证事实。

## 建议文件位置

- 推荐：`memory/architecture-baseline.md`
- 若团队希望统一到决策文件，可在 `memory/decisions.md` 中单独建立 `Architecture Baseline` 分区。

|----------|------|------|----------|

- 共享数据库表

- 发布链路中的脚本和配置

- 当前还缺哪些事实？

## 最小落地建议

如果时间很紧，至少先写完这 5 项：

1. 技术栈与运行时
2. 模块与边界
3. 核心调用链
4. 外部依赖与约束
5. 允许与禁止

## 与其他 memory 文件的关系

- `memory/architecture-baseline.md`
  - 记录“系统当前是什么样”。
- `memory/decisions.md`
  - 记录“为什么这样选，以及后续确认过什么决策”。
- `memory/engineering.md`
  - 记录“团队如何开发、测试、发布和协作”。
