# 需求卡模板

> 同一张卡同时用于 GitHub Issue 与飞书群公告，Issue 编号为对账键。

```markdown
## 需求卡

- 标题：
- Issue：#
- 飞书群：
- 负责人（决策人）：
- 背景与目标：
- 验收标准（可测试，逐条）：
  1.
  2.
- 不做项：
- 复杂度：小（≤5 人日）/ 大（>5 人日或命中例外）
- 例外命中：数据迁移 / 权限 / 资金 / 生产配置 / 对外接口 / 无
- Plan-ID（大需求必填）：
- 当前所处的门：G1 Spec 放行 / G2 代码放行 / G3 发布放行
- 关联 PR：
- Spec/方案文档路径：
- 风险与假设：
- 时间线：立项 YYYY-MM-DD / G1 / G2 / G3 / 上线
```

填写要点：

- 验收标准无法写成可检查的条目，则不得通过 G1。
- 「当前所处的门」每过一门更新一次，并在时间线记日期（供 [度量](./ai-native-metrics.md) 使用）。
