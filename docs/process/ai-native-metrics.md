# AI-native 度量（最小四指标）

> 不看「AI 生成代码占比」。关注端到端交付与质量。先手工记录，不建看板；有基线后再谈自动化。

| 指标 | 定义 | 记录位置 |
|------|------|----------|
| 端到端周期 | 需求卡立项日 → 上线日 | 需求卡时间线；`memory/changelog.md` |
| AI 初稿采纳率 | 定稿是在 AI 初稿上迭代（采纳）还是推翻重写；按「采纳 / 大改 / 重写」三档记 | 复盘三行 |
| 返工次数 | 同一需求在 G1/G2/G3 被打回的次数 | 需求卡 / Issue 评论 |
| 变更失败/回滚率 | 上线后需回滚或紧急修复的变更占比 | `memory/changelog.md` |

归因链：Session 摘要 → Commit/PR（含 Plan-ID）→ Issue（需求卡）。PR 模板已要求填写关联项，保证可追溯。

使用约定：

- 每个需求收尾时由负责人补一行，月度汇总一次。
- 指标用于发现流程问题，不用于个人考核。
- 积累至少 10 个需求再设阈值或目标。
