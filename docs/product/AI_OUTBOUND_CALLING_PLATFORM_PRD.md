# AI 智能外呼平台 · 产品方案（PRD）

> 依据《产品设计原则》：用户与场景先行、目标可衡量、优先级清晰、闭环与反馈、一致性。  
> 产出物结构：背景、目标、用户与场景、功能列表、非功能需求、成功指标。

---

## 一、背景与目标

### 1.1 背景

- 企业外呼场景（营销、回访、通知、调研等）人力成本高、效率有限、话术与合规难以统一。
- 语音大模型与 ASR/TTS 成熟，使「AI 代替人工外呼」在部分场景具备可行性。
- 市场存在对「可配置、可追溯、可管控」的智能外呼平台的需求，兼顾效果与合规。

### 1.2 产品目标（可衡量）

| 目标 | 衡量方式 |
|------|----------|
| **提升外呼效率** | 单坐席/单日有效触达量较人工提升 ≥ X%（需基线数据） |
| **降低成本** | 单通外呼成本较纯人工下降 ≥ Y%（需基线数据） |
| **可控与合规** | 100% 通话可录音、可追溯；支持敏感信息脱敏与合规策略配置 |
| **可运营** | 业务方可在 X 天内完成新话术/新场景配置并上线（需定义 X） |

## 二、目标用户与典型场景

### 2.1 目标用户

| 用户角色 | 描述 | 核心诉求 |
|----------|------|----------|
| **外呼运营/业务方** | 负责营销、回访、通知等外呼任务的一线运营或业务负责人 | 快速配置任务与话术、查看效果数据、调整策略 |
| **客服/电销主管** | 管理外呼团队、关注接通率与转化 | 任务分配、实时监控、报表与复盘 |
| **平台管理员** | 负责账号、权限、线路与合规配置 | 资源与权限管理、合规策略、审计日志 |
| **（间接）被叫用户** | 接听外呼的 C 端用户 | 体验自然、可随时打断/挂断、信息清晰 |

### 2.2 典型场景

1. **营销外呼**：活动通知、优惠推荐、会员续费提醒等，AI 完成首轮触达与意向筛选，高意向转人工。
2. **回访/通知**：订单状态、预约提醒、欠费提醒、满意度回访等，以信息传达与简单确认为主。
3. **调研/问卷**：满意度调查、市场调研等，AI 按脚本提问并记录答案。
4. **催收/提醒**：还款提醒、续保提醒等（需严格合规与话术管控）。

## 三、功能列表（含优先级）

### 3.1 功能总览与优先级说明

- **P0**：首版上线必备，无则无法完成核心业务流程。
- **P1**：首版或紧接版本需要，显著提升效果或运营效率。
- **P2**：可在后续迭代中实现，用于体验与效率进阶。

### 3.2 核心功能

| 模块 | 功能点 | 优先级 | 说明 |
|------|--------|--------|------|
| **任务与话术** | 外呼任务创建与配置 | P0 | 选择名单、外呼时间、并发、重试策略等 |
| | 话术/剧本配置 | P0 | 支持多轮对话节点、分支、关键词触发与转人工条件 |
| | 变量与个性化 | P1 | 名单字段映射（如姓名、订单号），话术内变量替换 |
| **外呼执行** | 自动外呼与排队 | P0 | 按任务策略拨号、排队、并发控制 |
| | AI 对话引擎 | P0 | 语音识别(ASR)、意图理解、话术执行、语音合成(TTS)、支持打断 |
| | 转人工 | P0 | 满足条件时转接人工坐席，带上下文与录音 |
| **名单与资源** | 名单管理 | P0 | 上传/导入、去重、号码状态（有效/无效/黑名单） |
| | 线路与号码管理 | P0 | 外显号码、线路归属、并发与频率限制（配合运营商/合规） |
| **监控与报表** | 任务监控大屏 | P0 | 实时接通率、进行中通话数、排队数、异常告警 |
| | 任务报表 | P0 | 按任务维度的拨打量、接通量、通话时长、意向标签、转化等 |
| | 通话明细与录音 | P0 | 每通通话可查、可听录音、可追溯 |
| **合规与安全** | 通话录音与存储 | P0 | 全量录音、可配置保留周期、敏感信息脱敏 |
| | 合规策略配置 | P1 | 拨打时段、频率、黑名单、禁拨词、用户 opt-out 处理 |
| | 权限与审计 | P1 | 角色与权限、操作日志与审计 |
| **运营体验** | 话术/场景模板 | P1 | 常用场景模板，一键复制后微调 |
| | A/B 话术与效果对比 | P2 | 同一任务多套话术分流，对比转化与满意度 |
| | 意图/话术分析看板 | P2 | 高频意图、未覆盖问题、话术优化建议 |

### 3.3 功能与场景对应（简要）

- **营销外呼**：任务+话术(P0)、名单(P0)、转人工(P0)、报表(P0)、合规(P1)。
- **回访/通知**：同上，话术更偏线性告知与确认。
- **调研/问卷**：话术支持多轮问答与选项记录(P0)，报表支持问卷统计(P1)。
- **催收/提醒**：在通用能力上加强合规策略(P1)、禁拨词与时段(P1)、审计(P1)。

## 三（附）、功能细节说明

以下对各模块做产品级细化：字段、状态、规则、交互与边界情况。

### 3.A 任务与话术

#### 3.A.1 外呼任务创建与配置

| 项目 | 说明 |
|------|------|
| **任务基本信息** | 任务名称（必填）、任务描述（选填）、所属业务/项目（选填，用于权限与报表聚合）。 |
| **名单与范围** | 选择已上传的名单（单选或多选合并）；可选「名单过滤条件」：仅拨打状态为「待拨打」的号码、排除近 N 天内已拨打过的号码（防重复骚扰）。 |
| **外呼时间** | 支持按「立即执行」或「定时执行」；定时支持单次指定日期时间，或周期（每日/每周 N 天） + 每日时间段，如 9:00–12:00、14:00–18:00；需校验不超出合规允许的拨打时段。 |
| **并发与节奏** | 最大并发路数（如 10/50/100，受线路与资源限制）；单号码重试次数（如 0/1/2）、重试间隔（如 30 分钟）、重试时段是否沿用任务时段。 |
| **线路与号码** | 选择外显线路/号码池（可多选，系统按策略轮询或按归属地匹配）；未选时使用账号默认线路。 |
| **话术与转人工** | 绑定一条话术/剧本；转人工策略（见下）在话术内配置或任务级覆盖。 |
| **任务状态** | 草稿 → 已配置 → 已启动 → 执行中 → 已暂停 → 已结束；仅「已配置」可编辑；「已启动」后可暂停/恢复，结束后不可再恢复。 |
| **操作与权限** | 创建、编辑、删除（仅草稿/已结束且无敏感数据依赖时可删）、启动、暂停、查看报表与明细；删除/导出名单需按权限与审计策略。 |

#### 3.A.2 话术/剧本配置

| 项目 | 说明 |
|------|------|
| **话术结构** | 树状或流程图：节点类型包括「开场白」「播放 TTS」「等待用户回复」「分支判断」「收集信息」「转人工」「结束」等。 |
| **节点 - 开场白** | 一段或多段 TTS 文本；支持变量占位符（如 `{姓名}`、`{订单号}`），由名单字段或上文收集结果替换。 |
| **节点 - 播放 TTS** | 纯播放，不等待；可配置播放后自动进入下一节点或等待用户打断。 |
| **节点 - 等待用户回复** | 超时时间（如 3s/5s）；超时后进入默认下一节点或播放「未听清，请再说一遍」后重试（可配置重试次数）。 |
| **节点 - 分支判断** | 根据「用户意图/关键词/槽位」决定下一节点。支持：关键词匹配（包含/等于/正则）、意图标签（需对接 NLU 输出）、已填槽位（如「是否同意」= 是/否）。可配置多分支 + 默认分支。 |
| **节点 - 收集信息** | 收集结果写入槽位（如「用户意向」= 高/中/低、「预约时间」= 日期时间）；校验规则可选（如必填、格式）。收集失败可重试或跳转指定节点。 |
| **节点 - 转人工** | 转人工条件：满足某分支（如用户说「转人工」）、某槽位满足（如意向=高）、超时次数达到 N 次等。转出时传递：任务 ID、话术节点、已收集槽位、当前录音 URL（可选）。 |
| **节点 - 结束** | 结束原因：正常结束、用户挂断、超时挂断等；可配置结束前播放一句再见语。 |
| **全局设置** | 未识别默认回复（如「抱歉没听清」）、最大对话轮数（防死循环）、是否允许用户随时说「不需要」并结束。 |
| **版本与发布** | 话术支持保存为草稿与发布；任务绑定「已发布」版本；话术修改后需重新发布，新任务可选新版本，进行中任务沿用旧版本。 |

#### 3.A.3 变量与个性化（P1）

| 项目 | 说明 |
|------|------|
| **变量来源** | 名单字段（上传时定义的列，如姓名、订单号、金额）；话术内上一节点写入的槽位。 |
| **使用方式** | 在 TTS 文本中用占位符，如 `{姓名}`、`{订单号}`；系统在播放前替换，若缺失则用默认文案或跳过该句。 |
| **名单字段映射** | 任务或话术配置时选择「本任务名单」与话术变量的映射关系（如 名单列「customer_name」→ 变量「姓名」）。 |

### 3.B 外呼执行

#### 3.B.1 自动外呼与排队

| 项目 | 说明 |
|------|------|
| **拨号策略** | 从任务名单中按状态筛选「待拨打」；取号顺序：按名单上传顺序 / 按优先级字段 / 随机（可配置）。 |
| **并发控制** | 任务级最大并发；系统级/线路级上限不突破；每接通一路占用 1 并发，挂断后释放。 |
| **排队与限流** | 当并发已满时，新号码进入队列；队列最大长度可配置，超长可丢弃或延后；避免同一号码在短时间内被多次尝试（与重试间隔一致）。 |
| **状态更新** | 拨打中 → 接通 / 未接通（忙、无应答、拒接、空号等）；接通后 → 对话中 → 已结束（正常结束/转人工/用户挂断/系统挂断）。名单状态同步更新，便于报表与重试。 |

#### 3.B.2 AI 对话引擎

| 项目 | 说明 |
|------|------|
| **通话建立** | 平台发起呼叫，被叫接听即建立 RTP/媒体通道；播放开场白前可加 0.5–1s 缓冲，减少首字截断。 |
| **ASR** | 实时或准实时语音识别；支持静音检测（VAD）减少无效识别；可配置语言（如普通话/粤语）、领域词表提升专有名词准确率。 |
| **NLU/意图** | 对接意图识别与槽位抽取；输出意图标签 + 槽位键值，供话术分支判断与收集信息节点使用；未识别时走默认分支或默认回复。 |
| **TTS** | 将话术节点中的文本合成为语音播放；支持语速、音色（若有多音色）；支持 SSML 或简单标记（如停顿、数字读法）。 |
| **打断** | 用户说话时可打断当前播放；打断后根据当前节点配置：重新播放、跳转下一节点或进入「等待用户回复」逻辑。 |
| **静音与超时** | 用户长时间静音：按节点配置的超时时间与重试次数处理；超过最大轮数可播放结束语并挂断。 |
| **异常** | 识别/合成/网络异常时：可播放「暂时无法继续，请稍后再试」并挂断，或转人工（若已配置）；所有异常需打点与日志，便于排查。 |

#### 3.B.3 转人工

| 项目 | 说明 |
|------|------|
| **触发条件** | 话术内「转人工」节点被命中（分支或槽位条件）；或全局配置「用户说转人工/人工客服」等关键词。 |
| **转接方式** | 支持：呼转至指定坐席/技能组、或入客服排队队列；携带主叫、被叫、任务 ID、话术节点、槽位摘要、录音 URL（可选）。 |
| **坐席端展示** | 弹屏或侧栏展示：客户号码、任务名称、意向/槽位摘要、当前话术节点；可点击听当前任务已录片段或完整录音。 |
| **未接通处理** | 若转接后坐席全忙或超时未接：可播放「坐席忙，请稍后」并挂断，或再入队列等待；行为可配置。 |

### 3.C 名单与资源

#### 3.C.1 名单管理

| 项目 | 说明 |
|------|------|
| **名单实体** | 名单名称、描述、所属业务、创建人、创建时间；名单状态：导入中、就绪、已关联任务（只读/可解绑）、已归档。 |
| **上传与导入** | 支持 Excel/CSV；必含列「手机号」；其他列可自定义（如姓名、订单号、金额、备注）；单次上传条数限制（如 10 万）、文件大小限制；编码 UTF-8/GBK 自动检测。 |
| **校验与去重** | 手机号格式校验（大陆 11 位等）；去重策略：同名单内按手机号去重保留首条/末条；可选与系统黑名单校验，命中则不导入或标记为「黑名单」。 |
| **号码状态** | 待拨打、拨打中、已接通、未接通、已过期（超过任务允许重试窗口）、已加入黑名单、手动置为无效；支持按状态筛选与导出。 |
| **名单与任务** | 一个名单可被多个任务使用；任务启动时按任务配置的过滤条件生成「本次拨打范围」快照，避免任务运行中名单变更影响结果。 |

#### 3.C.2 线路与号码管理

| 项目 | 说明 |
|------|------|
| **线路/号码池** | 外显号码、线路类型（如固话/95/96/106 等）、运营商/供应商、归属地、容量（并发数或日呼叫量）。 |
| **绑定与策略** | 线路可绑定到租户/项目；任务选线策略：指定线路、按归属地自动选、轮询。 |
| **限频与合规** | 单号码单日/单任务拨打次数上限；单号码拨打间隔（如 7 天内不重复）；与合规策略中的「拨打时段」「黑名单」联动校验。 |

### 3.D 监控与报表

#### 3.D.1 任务监控大屏

| 项目 | 说明 |
|------|------|
| **实时指标** | 当前任务：进行中通话数、排队数、今日已拨打、今日已接通、当前接通率、平均通话时长；可多任务切换或汇总。 |
| **异常告警** | 接通率骤降、ASR/TTS 失败率超阈值、线路不可用、队列堆积超长等；告警方式：站内信、邮件、 webhook（可选）。 |
| **展示形式** | 大屏/看板：卡片、折线图（按分钟/小时）、表格；支持自动刷新（如 30s）。 |

#### 3.D.2 任务报表

| 项目 | 说明 |
|------|------|
| **维度** | 按任务、按日期、按线路、按话术版本（若支持）。 |
| **指标** | 名单总量、已拨打、未拨打、接通数、未接通数（细分：忙/无应答/拒接/空号等）、接通率、平均通话时长、转人工数、意向分布（若已打标签）、问卷题统计（若为调研场景）。 |
| **筛选与导出** | 时间范围、任务多选、导出为 Excel/CSV；导出需权限与审计。 |

#### 3.D.3 通话明细与录音

| 项目 | 说明 |
|------|------|
| **明细字段** | 任务名、名单行 ID、手机号（可脱敏）、拨打时间、接通时间、挂断时间、通话时长、挂断方、结束原因、转人工与否、意向/槽位摘要、录音 URL、话术节点路径（可选）。 |
| **操作** | 列表筛选（任务、时间、接通状态、是否转人工）；点击录音在线播放或下载；支持按合规要求脱敏展示与导出。 |

### 3.E 合规与安全

#### 3.E.1 通话录音与存储

| 项目 | 说明 |
|------|------|
| **录制策略** | 全量录制；录制格式与编码（如 PCM/AAC、采样率）；单通录音与任务、名单行、通话时间关联存储。 |
| **保留周期** | 可配置 N 天，到期自动删除或归档；不同业务/合规要求可设不同策略。 |
| **敏感信息脱敏** | 播放与存储：身份证号、银行卡号等按规则脱敏；报表与明细中手机号可选中间 4 位 * 号；导出时可二次脱敏策略。 |

#### 3.E.2 合规策略配置（P1）

| 项目 | 说明 |
|------|------|
| **拨打时段** | 全局或按任务：允许拨打的小时区间（如 9–21）；与地域/行业策略可扩展。 |
| **频率与黑名单** | 单号码单日/单周拨打上限；全局与业务黑名单（号码级）；用户 opt-out 后自动入黑名单并禁止再拨。 |
| **禁拨词** | 话术或 TTS 中禁止出现的词；配置后发布前校验或运行中检测（可选），命中则禁止发布或告警。 |

#### 3.E.3 权限与审计（P1）

| 项目 | 说明 |
|------|------|
| **角色与权限** | 角色示例：超级管理员、业务管理员、运营、只读；权限粒度：任务（创建/编辑/启动/查看）、名单（上传/查看/导出）、报表、线路、合规策略、用户管理。 |
| **操作日志** | 谁、何时、对哪项资源、做了何操作（创建/修改/删除/启动/导出等）；日志可查、可导出，保留期可配置。 |

---

### 3.F 运营体验（P1/P2）

| 项目 | 说明 |
|------|------|
| **话术/场景模板** | 预置或用户保存的「话术模板」：包含节点结构、示例文案、常见分支；创建话术时可从模板复制再编辑。 |
| **A/B 话术（P2）** | 同一任务绑定多套话术，按比例分流（如 50% A / 50% B）；报表按话术版本统计接通率、意向率、转化，便于对比优化。 |
| **意图/话术分析看板（P2）** | 统计高频识别意图、未识别话术占比、常见用户说法；辅助优化话术与 NLU 词表。 |

## 四、非功能需求

| 类型 | 要求 |
|------|------|
| **性能** | 单任务支持至少 X 路并发（需按线路与资源定）；系统响应与 ASR/TTS 延迟在可接受范围内（如首包延迟 ≤ 2s） |
| **可用性** | 外呼与对话服务可用性目标 ≥ 99.5%；支持降级（如 AI 不可用时转人工或排队） |
| **安全** | 名单与通话内容加密存储与传输；访问与导出需权限与审计 |
| **合规** | 遵守各地外呼/营销/个人信息保护相关法规；支持用户拒呼、退订与黑名单；录音与话术可审计 |
| **可扩展** | 话术引擎支持后续接入更多 NLU/大模型能力；线路与地域可扩展 |

## 五、成功指标与验收标准

### 5.1 业务成功指标

- **效率**：单任务从配置到首次外呼的耗时 ≤ 约定天数（如 3 个工作日）。
- **效果**：接通率、意向率/转化率不低于业务基线（需按场景定基线）。
- **成本**：单通外呼成本较基线下降 ≥ 约定比例。
- **合规**：无合规红线问题（禁拨时段、黑名单、用户 opt-out 等 100% 生效）。

### 5.2 产品验收标准（首版）

- [ ] 支持至少 1 个完整外呼场景（如「回访/通知」）从名单导入到报表查看全流程跑通。
- [ ] 话术可配置多轮与转人工，通话可录音并可回溯。
- [ ] 任务与通话具备基础监控与报表。
- [ ] 具备名单、线路、权限等基础管理能力。
- [ ] 非功能需求中的安全与合规项有明确实现或配置方案。
