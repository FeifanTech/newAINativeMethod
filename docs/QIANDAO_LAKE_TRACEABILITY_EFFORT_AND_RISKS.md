# 千岛湖渔业溯源平台 · 工作量评估与技术风险分析

> 依据《技术架构原则》对 [技术方案](./QIANDAO_LAKE_TRACEABILITY_TECH_SOLUTION.md) 做初步评估。  
> 本文档为**初步评估**，实际排期需结合团队规模、蚂蚁链对接节奏与客户验收节点再细化。

---

## 一、评估前提与单位说明

| 项     | 说明 |
|--------|------|
| **单位** | 人天（1 人天 = 1 人 1 个工作日），范围表示不确定性 |
| **假设** | 后端 1～2 人、前端 1 人可并行；蚂蚁链 BaaS 环境与文档已就绪；客户能配合联调与验收 |
| **范围** | 覆盖技术方案「十、建议实施顺序」的 6 个阶段 + 基础设施与可观测 + 联调验收 |

## 四、技术风险分析

以下风险与《技术架构原则》中的「风险与回滚」「可观测」「安全与合规」对应，按影响与发生概率简要评估。

### 4.1 高风险

| 风险 | 描述 | 影响 | 发生概率 | 缓解措施 |
|------|------|------|----------|----------|
| **蚂蚁链对接延迟或能力不符** | 文档不全、沙箱/生产环境开通慢、存证/核验 API 与方案假设不一致 | 关键路径阻塞，阶段一及后续上链/核验全部受影响 | 中 | 尽早与蚂蚁链/客户对齐接口文档与环境；链适配层严格抽象，便于 mock 与替换；先约定接口契约再开发 |
| **链上核验超时导致溯源页超 3s** | 核验接口延迟或抖动，拖垮 C 端响应 | 不满足 PRD 性能要求（≤3s），体验差 | 中 | 核验超时（如 2s）强制降级，不阻塞溯源链展示；核验可异步或按节点并行；热点溯源码缓存核验结果（可选） |
| **上链失败或重试积压导致数据不一致** | 业务显示「已提交」但长期「待上链」，或重试逻辑缺陷导致漏上链/重复上链 | 链上与业务侧不一致，溯源核验失真，监管审计受影响 | 中 | 上链日志表完整记录请求/响应/状态；重试次数与告警阈值可配置；定期对账「待上链」与链上状态 |

### 4.2 中风险

| 风险 | 描述 | 影响 | 发生概率 | 缓解措施 |
|------|------|------|----------|----------|
| **主体与链身份映射配置复杂** | 政府/多主体在蚂蚁链侧的账户或权限配置与业务角色不对齐 | 上链身份错误或无法上链，排查成本高 | 中 | 方案中明确「平台统一发起存证、主体标识由业务传入」；与客户/蚂蚁链约定映射表与流程；在主体与节点服务中做清晰配置与校验 |
| **溯源链递归与性能** | 链条过长或关联查询设计不当，导致查询慢或 N+1 | 溯源查询超时或 DB 压力大 | 中 | 设计时控制递归深度，批次/关联表结构清晰；必要时冗余关键展示字段或缓存溯源链摘要 |
| **权限与数据范围遗漏** | 政府按区域、企业按主体可见范围未全覆盖，或导出/日志泄露跨范围数据 | 合规与安全风险 | 中 | 按角色与数据范围做接口级与数据级校验；导出与日志查询强制带范围过滤；评审时逐角色过用例 |
| **检测报告与敏感信息泄露** | 报告原文或个人信息未脱敏/未做权限控制 | 合规与隐私风险 | 中 | 报告存 OSS，访问链带鉴权与审计；展示与导出做脱敏；日志不含明文敏感信息 |

### 4.3 低风险（可控）

| 风险 | 描述 | 影响 | 发生概率 | 缓解措施 |
|------|------|------|----------|----------|
| **DB 或 OSS 故障** | 存储不可用 | 业务不可用或报告无法访问 | 低 | 主从/多副本、定期备份；溯源查询可读从库；关键路径有降级与告警 |
| **依赖升级或安全漏洞** | 框架/库漏洞需升级 | 短期需排期修洞与回归 | 低 | 依赖版本与漏洞扫描纳入迭代；链适配层与业务解耦，减少链 SDK 升级影响面 |
| **多链或链迁移** | 未来换链或多链并存 | 需改链适配层与配置，业务侧改动尽量小 | 低 | 链适配层已抽象，EvidencePayload 与链无关；链配置与多链扩展已在方案中预留 |

## 五、风险与架构原则对应

| 架构原则 | 风险应对中的体现 |
|----------|------------------|
| **简单优于复杂** | 首版用 DB+定时任务做上链重试，不引入重型 MQ；核验超时即降级，不增加复杂重试 |
| **边界清晰** | 链适配层单一依赖蚂蚁链，业务不直连链，降低「链能力不符」的扩散面 |
| **可观测** | 上链/核验/查询均有日志与指标，便于排查「上链失败」「核验超时」「溯源慢」 |
| **可演进** | 链配置与多链预留、接口版本化，降低「链迁移」「接口变更」的改造成本 |
| **安全与合规** | 权限与数据范围、敏感数据脱敏、操作与上链日志可审计，直接对应权限与泄露风险 |

## 六、建议

1. **先锁定蚂蚁链**：在排期前与蚂蚁链/客户确认 BaaS 环境、存证/核验 API 与示例，必要时先做 1～2 天 PoC，再定阶段一工期。
2. **首版控制范围**：优先交付「登记 → 上链 → 溯源查询 → 链上核验」+ 报表与日志，监管大屏与抽检可作为 P1 迭代，以控制首版工作量与风险。
3. **风险纳入迭代**：将「上链对账与告警」「核验超时降级」「权限与数据范围测试」纳入各阶段 Definition of Done，避免集中到后期。
4. **工作量再校准**：本文档为人天级粗估，待接口契约与表结构细化后，可按任务级再估一次并更新本文档。
