# 千岛湖渔业溯源平台 · 产品方案（PRD）

> 依据《产品设计原则》：用户与场景先行、目标可衡量、优先级清晰、闭环与反馈、一致性。  
> 产出物结构：背景、目标、用户与场景、功能列表、功能细节说明、非功能需求、成功指标。  
> **技术底座**：基于蚂蚁链（AntChain）构建链上存证与溯源核验。

---

## 一、背景与目标

### 1.1 背景

- **千岛湖渔业**：千岛湖作为重要水源地与渔业产区，政府需强化「从养殖/捕捞 → 加工 → 流通 → 消费」全链路监管，保障品质与品牌、打击假冒。
- **客户诉求**：政府方希望建设**可验真、不可篡改、多方共治**的渔业溯源体系，提升公信力与消费者信任。
- **技术选型**：客户明确要求**基于蚂蚁链**，利用其区块链存证、溯源与多方协作能力，实现数据上链存证与扫码核验。

### 1.2 产品目标（可衡量）

| 目标 | 衡量方式 |
|------|----------|
| **全链路可追溯** | 养殖/捕捞、加工、流通、销售各环节关键数据上链，消费者/监管方可查询与核验 |
| **数据不可篡改** | 关键操作与凭证经蚂蚁链存证，链上可验真 |
| **政府监管可视** | 监管大屏与报表覆盖主体、批次、检测、流向，支持抽检与预警 |
| **消费者可验真** | C 端扫码（或网页/小程序）可查看溯源链与关键证明，提升信任 |

## 二、目标用户与典型场景

### 2.1 目标用户

| 用户角色 | 描述 | 核心诉求 |
|----------|------|----------|
| **政府监管方** | 农业农村/渔业主管部门、市场监管等 | 主体与批次监管、检测与流向监控、违规预警、数据报表与审计 |
| **养殖/捕捞主体** | 养殖户、捕捞企业、合作社 | 便捷登记捕捞/出塘信息并上链，减少重复填报 |
| **加工/检测主体** | 加工企业、第三方检测机构 | 录入加工批次、检测报告并上链，与上游批次关联 |
| **流通/销售主体** | 批发商、零售商、电商/门店 | 录入入库、出库、销售记录并上链，与上游批次关联 |
| **消费者** | 购买千岛湖鱼产品的 C 端用户 | 扫码或输入溯源码查看全链路溯源信息与证明，验真 |

### 2.2 典型场景

1. **养殖/捕捞登记**：主体在平台登记出塘/捕捞批次（品种、数量、时间、水域等），关键信息上链存证。
2. **加工与检测**：加工企业录入加工批次并关联上游批次；检测机构上传检测报告，报告摘要或哈希上链。
3. **流通与销售**：流通主体录入入库/出库；销售环节生成溯源码/二维码，与批次绑定。
4. **消费者溯源**：消费者扫码或输入溯源码，查看从养殖/捕捞到当前环节的溯源链及链上存证核验结果。
5. **政府监管**：监管方查看主体清单、批次流向、检测结果、异常预警与统计报表；必要时抽检与审计链上数据。

## 三、功能列表（含优先级）

### 3.1 优先级说明

- **P0**：首版必备，无则无法形成「登记 → 上链 → 溯源查询」闭环。
- **P1**：首版或紧接版本需要，显著提升监管与体验。
- **P2**：后续迭代，用于体验与效率进阶。

### 3.2 核心功能总览

| 模块 | 功能点 | 优先级 | 说明 |
|------|--------|--------|------|
| **主体与节点** | 主体管理（政府、企业、检测机构） | P0 | 主体注册、认证、与蚂蚁链节点/身份关联 |
| | 蚂蚁链接入与账户 | P0 | 租户/联盟链配置、存证与查询接口对接 |
| **养殖/捕捞** | 捕捞/出塘登记 | P0 | 批次信息录入、关键数据上链存证 |
| | 批次与溯源码生成 | P0 | 批次号、溯源码/二维码生成规则与绑定 |
| **加工与检测** | 加工批次登记 | P0 | 加工批次录入、关联上游批次、上链 |
| | 检测报告上传与上链 | P0 | 报告上传、摘要或哈希上链、与批次关联 |
| **流通与销售** | 入库/出库登记 | P0 | 流通主体录入出入库、关联批次 |
| | 销售与溯源码绑定 | P0 | 销售记录、溯源码与批次绑定、上链 |
| **溯源查询** | C 端溯源查询（扫码/溯源码） | P0 | 展示溯源链、关键证明、链上核验结果 |
| | 链上存证核验 | P0 | 关键凭证在蚂蚁链上的核验展示 |
| **监管与报表** | 监管大屏 | P1 | 主体、批次、检测、流向概览与预警 |
| | 批次与流向报表 | P0 | 按批次/主体/时间查询与导出 |
| | 抽检与审计 | P1 | 抽检任务、链上数据审计与日志 |
| **合规与安全** | 权限与角色 | P0 | 政府/企业/检测不同角色与权限 |
| | 操作与上链日志 | P0 | 关键操作与上链记录可查、可审计 |

## 四、功能细节说明

以下对各模块做产品级细化：字段、状态、规则、与蚂蚁链的衔接点。

---

### 4.A 主体与蚂蚁链接入

#### 4.A.1 主体管理

| 项目 | 说明 |
|------|------|
| **主体类型** | 政府监管、养殖/捕捞企业（含合作社、农户代表）、加工企业、检测机构、流通/销售企业。 |
| **主体信息** | 统一社会信用代码、名称、类型、联系人、手机、所属区域（如淳安县/千岛湖某片区）；状态：待审核、已通过、已禁用。 |
| **认证与审核** | 政府端可配置「需审核」；企业/机构提交后由监管方审核通过方可参与上链与溯源；支持证照上传（营业执照、许可证等）留档。 |
| **与链关系** | 主体通过后，在蚂蚁链侧配置对应身份/账户（或映射到联盟成员），便于后续以「主体身份」发起存证与查询。 |

#### 4.A.2 蚂蚁链接入与账户

| 项目 | 说明 |
|------|------|
| **链类型** | 基于蚂蚁链 BaaS/联盟链，政府或平台方为盟主，养殖/加工/检测/流通等为参与节点或授权存证方（具体以蚂蚁链产品能力为准）。 |
| **存证内容** | 关键业务数据哈希或结构化摘要上链，如：批次创建、加工记录、检测报告哈希、流通节点等；原文或详单可存业务库，链上存证用于防篡改与核验。 |
| **存证时机** | 各环节「提交并上链」：登记完成后调用蚂蚁链存证接口，获得交易哈希/存证凭证；存证失败则业务状态为「待上链」，支持重试。 |
| **查询与核验** | 消费者/监管方溯源时，根据业务侧记录的存证凭证（如交易哈希）调用蚂蚁链核验接口，展示「链上核验通过」或失败原因。 |
| **配置与密钥** | 链 ID、节点/应用配置、API 密钥等由平台统一管理，主体无感知；若需多租户多链，可扩展「链配置」与主体绑定。 |

---

### 4.B 养殖/捕捞

#### 4.B.1 捕捞/出塘登记

| 项目 | 说明 |
|------|------|
| **登记主体** | 仅已认证的养殖/捕捞主体可登记；支持按主体筛选「我的批次」。 |
| **必填字段** | 批次名称/备注（选填）、品种（如鲢鱼、鳙鱼等）、数量（尾/斤）、出塘或捕捞日期、捕捞/养殖水域（如千岛湖 XX 区域）、单位（吨/公斤等）。 |
| **选填字段** | 养殖方式（如生态养殖）、捕捞证号、备注。 |
| **业务规则** | 同一主体同一天可多批次；提交后生成**批次号**（平台内唯一，如 QDL-主体简码-日期-序号）；提交即触发**上链存证**（存证内容含批次号、主体、品种、数量、日期、水域等摘要）。 |
| **状态** | 草稿、已提交（已上链）、已关联下游（已被加工/流通引用）。 |
| **列表与查询** | 按主体、日期范围、品种、状态查询；支持导出（含存证凭证）。 |

#### 4.B.2 批次与溯源码

| 项目 | 说明 |
|------|------|
| **批次号** | 平台统一生成，全局唯一；作为溯源链主键，贯穿加工、流通、销售。 |
| **溯源码** | 在**销售环节**生成（见 4.D.2），与具体批次或子批次绑定；格式可为一维码/二维码 + 后台编码，消费者扫码即带溯源码查询。 |
| **子批次** | 若加工/流通将一批拆成多批，可生成子批次号，与父批次关联，便于流向追踪。 |

---

### 4.C 加工与检测

#### 4.C.1 加工批次登记

| 项目 | 说明 |
|------|------|
| **登记主体** | 已认证的加工企业。 |
| **必填字段** | 加工批次名称/备注、加工类型（如分割、冷冻、包装）、加工日期、关联上游批次（单选或多选，可输入批次号或从列表选）、本批产出数量/单位。 |
| **业务规则** | 关联的上游批次须已上链；提交后生成加工批次号，并**上链存证**（加工批次号、主体、关联上游批次号、加工类型、日期、产出量等摘要）。 |
| **状态** | 草稿、已提交（已上链）、已关联下游。 |
| **溯源链** | 前端/溯源页展示时，根据「关联上游批次」递归拼接：养殖/捕捞 → 加工 → …。 |

#### 4.C.2 检测报告上传与上链

| 项目 | 说明 |
|------|------|
| **登记主体** | 已认证的检测机构或加工企业（自检）。 |
| **必填字段** | 关联批次（养殖批次或加工批次）、检测类型（如药残、重金属、感官）、检测结论（合格/不合格）、报告文件上传（PDF/图片）、检测日期。 |
| **上链策略** | 报告文件哈希（如 SHA256）上链存证，必要时报告摘要（结论、检测项、日期）一并上链；原文存业务库或对象存储，链上存证用于防篡改。 |
| **展示** | 溯源查询时展示「检测结论 + 报告编号/哈希 + 链上核验结果」；可提供报告原文查看或下载链接（权限可控）。 |
| **不合格处理** | 若结论为不合格，可在监管侧标记预警、限制该批次进入流通或触发复检流程（业务规则可配置）。 |

---

### 4.D 流通与销售

#### 4.D.1 入库/出库登记

| 项目 | 说明 |
|------|------|
| **登记主体** | 已认证的流通/销售企业。 |
| **入库** | 选择来源批次（上游加工或养殖批次）、入库数量、入库时间、仓库/库位（选填）；提交后**上链存证**（入库主体、关联批次、数量、时间）。 |
| **出库** | 选择本企业持有的批次（或库存批次）、出库数量、出库时间、去向（如某销售单号/门店/客户）；提交后**上链存证**。 |
| **库存** | 可选功能：根据入库/出库汇总「当前持有批次及剩余量」，便于出库时选择和监管查看。 |

#### 4.D.2 销售与溯源码绑定

| 项目 | 说明 |
|------|------|
| **销售登记** | 销售主体、销售批次（来自本主体库存或上游出库）、销售数量、销售时间、销售渠道（如门店/电商/团购）。 |
| **溯源码生成** | 在销售登记时或单独「生成溯源码」：支持按件生成（一物一码）或按批生成（一批一码）；溯源码与批次（或子批次）绑定，绑定关系**上链存证**。 |
| **溯源码形式** | 数字码 + 对应二维码/条形码；支持批量生成与打印；溯源码全局唯一，查询时反查批次并拉取完整溯源链。 |
| **状态** | 溯源码：未使用、已绑定、已查询（可选统计）。 |

---

### 4.E 溯源查询（C 端）

#### 4.E.1 查询入口与展示

| 项目 | 说明 |
|------|------|
| **入口** | 扫码（解析溯源码）或网页/小程序内输入溯源码。 |
| **展示内容** | ① 溯源链时间线：养殖/捕捞 → 加工 → 检测（若有）→ 流通 → 销售；② 各节点关键信息（主体名称、时间、品种/数量等脱敏后的摘要）；③ 检测结论与报告核验入口；④ **链上核验结果**：关键节点存证在蚂蚁链上的核验状态（如「已核验」+ 存证时间）。 |
| **体验** | 若溯源码无效或已注销，提示「无效溯源码」；若链上核验失败或超时，可展示「链上核验暂不可用，请稍后再试」，避免误导。 |

#### 4.E.2 链上存证核验

| 项目 | 说明 |
|------|------|
| **核验逻辑** | 根据业务库中记录的存证凭证（如蚂蚁链交易哈希），调用蚂蚁链核验接口；展示「链上核验通过」及存证时间，或「核验失败」及原因。 |
| **展示层级** | 可按节点展示（如养殖节点已核验、加工节点已核验）；或整链展示一条「本溯源链关键数据已上链存证并核验通过」。 |
| **防伪** | 链上核验通过可作为「未被篡改」的证明，配合品牌与包装，降低仿冒品冒充风险。 |

---

### 4.F 监管与报表

#### 4.F.1 监管大屏（P1）

| 项目 | 说明 |
|------|------|
| **内容** | 主体总数、本月/本日登记批次数、检测合格率、溯源查询次数；地图或列表展示主要主体与流向；异常预警（如不合格批次、长时间未检测的品种等）。 |
| **权限** | 仅政府监管角色可看；可按区域/层级配置可见范围。 |

#### 4.F.2 批次与流向报表

| 项目 | 说明 |
|------|------|
| **维度** | 按主体、按批次、按时间范围、按品种、按环节（养殖/加工/流通/销售）。 |
| **指标** | 批次数、数量汇总、关联的检测结论、流向路径（从养殖到当前节点）；支持钻取到明细与存证凭证。 |
| **导出** | 支持导出 Excel/CSV；导出操作留审计日志。 |

#### 4.F.3 抽检与审计（P1）

| 项目 | 说明 |
|------|------|
| **抽检** | 监管方可发起抽检任务（选择批次或主体），指派检测或现场检查；抽检结果可录入并上链，与现有检测报告能力复用。 |
| **审计** | 关键操作日志（谁、何时、对哪条数据、做了何操作）；上链记录日志（存证内容摘要、交易哈希、成功/失败）；支持按主体、时间、操作类型查询与导出。 |

---

### 4.G 合规与安全

#### 4.G.1 权限与角色

| 项目 | 说明 |
|------|------|
| **角色** | 超级管理员（平台）、政府监管员、政府只读、企业管理员、企业操作员、检测机构；可扩展。 |
| **权限** | 主体管理（审核、禁用）、养殖/加工/流通/检测各环节的录入与查看、溯源码生成、监管大屏与报表、抽检与审计、系统配置。 |
| **数据范围** | 政府可按区域/层级只看辖区内主体与批次；企业仅能看本主体及与本主体相关的上下游批次。 |

#### 4.G.2 操作与上链日志

| 项目 | 说明 |
|------|------|
| **操作日志** | 登录、关键业务操作（提交批次、上传检测、生成溯源码等）；谁、何时、IP、操作类型、涉及主体/批次。 |
| **上链日志** | 存证内容摘要、蚂蚁链返回的交易哈希/凭证、成功/失败；便于对账与排查。 |
| **保留期** | 日志保留期可配置，满足合规与审计要求。 |

## 五、非功能需求

| 类型 | 要求 |
|------|------|
| **性能** | 溯源查询响应时间 ≤ 3s（含链上核验）；批量上链支持队列与重试，不阻塞业务提交 |
| **可用性** | 业务系统可用性目标 ≥ 99%；链上核验失败时降级为「暂不展示链上核验」，不影响溯源链展示 |
| **安全** | 传输 HTTPS；敏感数据加密存储；接口与操作鉴权；密钥与链配置安全管理 |
| **合规** | 个人信息与主体信息按合规要求脱敏与留存；政府数据与审计满足监管要求 |
| **可扩展** | 主体类型与环节可配置扩展；与蚂蚁链的对接抽象为「存证/核验」接口，便于升级链或多链 |

## 六、成功指标与验收标准

### 6.1 业务成功指标

- **全链路覆盖**：至少覆盖「养殖/捕捞 → 加工 → 销售 → 消费者扫码」一条完整链路，各环节有关键数据上链。
- **链上可验**：消费者扫码可看到至少 2 个环节的「链上核验通过」展示。
- **监管可用**：政府可查看主体列表、批次列表、检测结果与流向，并可导出报表。

### 6.2 产品验收标准（首版）

- [ ] 主体管理、蚂蚁链存证/核验对接完成，养殖/捕捞登记可上链并核验。
- [ ] 加工批次登记、检测报告上传与上链完成，与上游批次关联正确。
- [ ] 流通入库/出库、销售与溯源码绑定完成，溯源码可生成并绑定批次。
- [ ] C 端溯源查询页可展示完整溯源链与链上核验结果（含异常提示）。
- [ ] 监管方可使用批次与流向报表；权限与操作/上链日志可查。

## 七、与蚂蚁链的对接要点（建议）

| 环节 | 建议对接方式 |
|------|--------------|
| **存证** | 使用蚂蚁链 BaaS 提供的存证 API，将批次/加工/检测/流通/溯源码绑定等关键数据的哈希或结构化摘要上链，获取交易哈希或存证凭证并落库。 |
| **核验** | 消费者或监管方溯源时，用业务库中的存证凭证调用蚂蚁链核验 API，返回核验结果与存证时间，前端展示。 |
| **身份与权限** | 主体与链上身份/账户的映射由平台或政府侧在蚂蚁链控制台配置，业务系统只传「主体标识 + 业务数据」，由平台统一发起存证。 |
| **联盟与节点** | 具体联盟成员、节点数量、共识与权限以蚂蚁链产品文档与客户商务为准；本方案预留「链配置」与多链扩展。 |
