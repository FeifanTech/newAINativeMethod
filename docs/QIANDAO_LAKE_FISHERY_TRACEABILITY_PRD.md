# 千岛湖全鱼品溯源平台 · 产品方案（PRD）

> 依据《产品设计原则》：用户与场景先行、目标可衡量、优先级清晰、闭环与反馈、一致性。  
> 产出物结构：背景、目标、用户与场景、功能列表、功能细节说明、非功能需求、成功指标。  
> **需求来源**：参考《千岛湖--全鱼品溯源体系建设需求思考 V6.0》（商达公用）。  
> **技术底座**：基于蚂蚁链（AntChain）构建链上存证与溯源核验；数据标准与「浙食链」及未来全国平台兼容。  
> **范围边界**：**流通环节（储运、入库/出库、配送等）由蚂蚁数科团队已建成**；本 PRD 仅覆盖流通环节**之前**的环节（种源/投放、养殖/捕捞、加工、检测）及**与流通环节的对接**、溯源码与销售绑定（责任边界见下）、溯源查询与监管。

---

## 一、背景与目标

### 1.1 背景

- **客户与项目**：**商达公用集团**（山东公用控股旗下，中国水产与流通协会设施渔业分会会长单位）战略定位「中国 RAS 未来水产引领企业」。**千岛湖智慧鱼谷**项目总投资约 9.73 亿、占地约 619 亩、养殖水体 8.1 万立方米、年产约 1.8 万吨，以千岛湖地理标志「千岛湖鲢鳙」为基础，拓展淳安渔业一二三产深度融合，配备深加工车间（减盐臭鳜鱼、烟熏三文鱼、蒲烧鳗鱼等），已纳入浙江省千项万亿省重点项目。
- **溯源诉求**：建设**可验真、不可篡改、多方共治**的全鱼品溯源体系，覆盖**两类养殖模式**——① **千岛湖天然有机养殖（保水渔业）**：生态放养、鲢鳙为核心、不投人工饲料；② **RAS 工厂化循环水养殖（引水渔业）**：引用千岛湖深层低温水、封闭循环系统高密度可控养殖。实现「从水体到餐桌」全链条透明化，提升公信力与消费者信任。
- **技术选型**：客户与**蚂蚁集团**等专业公司对接，要求**基于蚂蚁链**（国内区块链领先、浙食链早期技术承建方）构建溯源平台；数据标准与**浙食链**及未来全国平台兼容。

### 1.2 产品目标（可衡量）

| 目标 | 衡量方式 |
|------|----------|
| **全链路可追溯** | 种源/投放、养殖/生长、加工、检测各环节由本平台登记并上链；**流通环节**数据通过对接蚂蚁数科流通系统获取并展示；消费者/监管方可查询完整溯源链（含流通节点）与核验；支持「单尾追溯」与「批次追溯」并行 |
| **数据不可篡改** | 关键操作与凭证经蚂蚁链存证，链上可验真 |
| **双模式覆盖** | 保水渔业（湖泊生态养殖）与引水渔业（RAS 工厂养殖）两条溯源路径均可配置与展示 |
| **认证与公信** | 有机认证、地理标志、GAP 等证书数字化绑定，扫码可关联展示与实时更新有效期 |
| **政府监管可视** | 监管大屏与报表覆盖主体、批次、检测、流向，支持抽检与预警 |
| **消费者可验真** | C 端一键扫码可查看「鱼的一生」溯源链、链上核验、认证与生态贡献等，提升信任 |

## 二、目标用户与典型场景

### 2.1 目标用户

| 用户角色 | 描述 | 核心诉求 |
|----------|------|----------|
| **政府监管方** | 农业农村/渔业主管部门、市场监管等 | 主体与批次监管、检测与流向监控、违规预警、数据报表与审计；与浙食链等平台数据互通 |
| **商达/养殖企业** | 千岛湖智慧鱼谷及合作养殖户、捕捞企业、合作社 | 保水渔业与 RAS 双模式数据采集与上链；减少重复检测与纸质记录（目标 70%+）；24 小时内问题产品全链定位与召回；品牌溢价与大型商超/生鲜电商准入 |
| **加工/检测主体** | 加工企业（深加工车间）、第三方检测机构 | 传统路径（活鱼起捕→吊水瘦身→冰鲜）与现代路径（麻醉休眠→低温分割→气调/速冻）的批次管理；加工环境监测；检测报告并上链 |
| **流通/销售（蚂蚁数科）** | 流通环节由蚂蚁数科团队已建成（储运、入库/出库、配送等） | 本平台不重复建设流通登记；通过对接获取流通数据用于溯源链展示与报表 |
| **本平台·销售与溯源码** | 加工/养殖出口至流通前的溯源码生成与批次绑定；或与蚂蚁数科侧溯源码/销售数据对接 | 溯源码生成与绑定责任边界以与蚂蚁数科约定为准（见 4.E） |
| **消费者** | 购买千岛湖鱼产品的 C 端用户 | 一键扫码读取全链路溯源（含本平台环节 + 流通环节展示）；自动关联有机认证、地理标志、GAP 等证书；可见「鱼的一生」时间轴与生态贡献；基于溯源的烹饪建议与营养分析 |

### 2.2 典型场景（双模式）

**保水渔业（千岛湖天然有机）**  
原良种场鱼苗 → 库湾标粗（6–12 个月）→ 科学投放（基于生态容量模型）→ 自然生长（2–4 年）→ 声呐探测与生态评估 → 定置张网捕捞 → 活水运输船暂养 → 码头吊水净化（7–15 天）→ 冷链配送。溯源重点：水域环境（浮游生物、水温分层、溶解氧）、鱼类生长轨迹、生态捕捞时间与区域、有机认证与地理标志绑定。

**引水渔业（RAS 工厂化循环水）**  
SPF 种苗引进 → 隔离检疫与驯化（30 天）→ 分级培育系统 → 智能投喂与生长监测 → 水质多参数自动调控 → 健康状态 AI 预警 → 停食净化处理 → 低温麻醉与无水保活运输 → 加工中心精细处理。溯源重点：全封闭水处理参数（pH、氨氮、亚硝酸盐、温度）、精准饲喂与营养调控、生物安保与疾病预防、能效与水资源循环。

**通用环节**  
加工与处理（双路径可配置）由本平台覆盖；**储运与配送由蚂蚁数科流通系统覆盖，本平台对接展示**；销售与溯源码绑定责任边界见 4.E；消费者扫码溯源与认证展示、政府监管与报表由本平台覆盖。

## 三、功能列表（含优先级）

### 3.1 优先级说明

- **P0**：首版必备，无则无法形成「登记 → 上链 → 溯源查询」闭环。
- **P1**：首版或紧接版本需要，显著提升监管与体验。
- **P2**：后续迭代，用于体验与效率进阶。

### 3.2 核心功能总览

| 模块 | 功能点 | 优先级 | 说明 |
|------|--------|--------|------|
| **主体与节点** | 主体管理（政府、企业、检测机构） | P0 | 主体注册、认证、与蚂蚁链节点/身份关联 |
| | 蚂蚁链接入与账户 | P0 | 租户/联盟链配置、存证与查询接口对接；与浙食链数据标准兼容 |
| **种源与投放** | 种质/苗种登记与投放决策 | P1 | 亲本/苗种登记、生态容量模型投放决策（保水渔业）、RAS 种苗检疫与驯化记录 |
| **养殖/捕捞** | 双模式养殖登记（保水/RAS） | P0 | 保水渔业：水域监测、生态捕捞、吊水净化；RAS：水质多参数、投喂与生长、AI 预警、停食净化 |
| | 批次与溯源码生成 | P0 | 批次号、单尾追溯与批次追溯并行、溯源码/二维码生成与绑定 |
| **加工与检测** | 加工批次登记（双路径） | P0 | 传统路径（起捕→吊水瘦身→冰鲜）与现代路径（麻醉→低温分割→气调/速冻）；加工环境监测 |
| | 检测报告上传与上链 | P0 | 报告上传、摘要或哈希上链、与批次关联 |
| **流通环节对接** | 与蚂蚁数科流通系统对接 | P0 | 获取储运、入库/出库、流向等数据，用于溯源链展示与监管报表；**流通环节本身由蚂蚁数科已建成，本平台不建设** |
| **销售与溯源码** | 溯源码生成与批次绑定、与流通侧协同 | P0 | 责任边界以与蚂蚁数科约定为准：本平台在加工出口/流出时生成溯源码并绑定批次，或对接流通侧已绑定的溯源码与销售数据 |
| **认证与标签** | 多重认证数字化集成 | P1 | 有机认证、地理标志、GAP 等证书绑定与实时更新有效期；国家地理标识/区域公用品牌/绿色/有机/防伪溯源码 |
| **溯源查询** | C 端「鱼的一生」与链上核验 | P0 | 扫码可见溯源链时间轴、链上核验、认证展示、生态贡献（如滤食浮游生物量）、烹饪建议与营养分析（P2） |
| **监管与报表** | 监管大屏、批次与流向、抽检与审计 | P0/P1 | 主体/批次/检测/流向概览与预警；按批次/主体/时间查询与导出；抽检任务与链上审计 |
| **标准与实施** | 千岛湖全鱼品溯源标准体系 | P1 | 基础通用（术语与编码、数据采集、信息安全）、分类管理（湖泊/RAS/加工储运）、技术实施（物联网/区块链/多平台交换）；与浙食链及全国平台兼容 |
| **实施路线** | 三阶段与试点 | P1 | 第一阶段：大型养殖与加工、基本追溯；第二阶段：中小散户与物流、深化数据；第三阶段：文旅/电商对接、数据增值；试点先行（1–2 家或核心品类）、标准统一 |
| **合规与安全** | 权限与角色、操作与上链日志 | P0 | 政府/企业/检测不同角色与权限；关键操作与上链记录可查、可审计 |

## 四、功能细节说明

以下对各模块做产品级细化：字段、状态、规则、与蚂蚁链的衔接点。

---

### 4.A 主体与蚂蚁链接入

#### 4.A.1 主体管理

| 项目 | 说明 |
|------|------|
| **主体类型** | 政府监管、养殖/捕捞企业（含合作社、农户代表）、加工企业、检测机构；流通/销售主体在蚂蚁数科流通系统中维护，本平台如需展示可与对接数据关联。 |
| **主体信息** | 统一社会信用代码、名称、类型、联系人、手机、所属区域（如淳安县/千岛湖某片区）；状态：待审核、已通过、已禁用。 |
| **认证与审核** | 政府端可配置「需审核」；企业/机构提交后由监管方审核通过方可参与上链与溯源；支持证照上传（营业执照、许可证等）留档。 |
| **与链关系** | 主体通过后，在蚂蚁链侧配置对应身份/账户（或映射到联盟成员），便于后续以「主体身份」发起存证与查询。 |

#### 4.A.2 蚂蚁链接入与账户

| 项目 | 说明 |
|------|------|
| **链类型** | 基于蚂蚁链 BaaS/联盟链，政府或平台方为盟主，养殖/加工/检测/流通等为参与节点或授权存证方（具体以蚂蚁链产品能力为准）。 |
| **存证内容** | **本平台环节**关键业务数据哈希或结构化摘要上链，如：种源/投放、批次创建、加工记录、检测报告哈希、溯源码绑定（若在本平台）等；流通环节由蚂蚁数科侧存证，本平台不重复存证流通节点。原文或详单可存业务库，链上存证用于防篡改与核验。 |
| **存证时机** | 各环节「提交并上链」：登记完成后调用蚂蚁链存证接口，获得交易哈希/存证凭证；存证失败则业务状态为「待上链」，支持重试。 |
| **查询与核验** | 消费者/监管方溯源时，根据业务侧记录的存证凭证（如交易哈希）调用蚂蚁链核验接口，展示「链上核验通过」或失败原因。 |
| **配置与密钥** | 链 ID、节点/应用配置、API 密钥等由平台统一管理，主体无感知；若需多租户多链，可扩展「链配置」与主体绑定。 |

### 4.B 种源与投放（P1）

| 项目 | 说明 |
|------|------|
| **种源登记** | 亲本/苗种来源（如国家级原良种场、SPF 种苗引进）；可选种质 DNA/基因标记信息（P2）；符合 DB3301/T 1139—2024 等地方标准。 |
| **投放决策（保水渔业）** | 基于千岛湖生态容量模型的科学投放；库湾标粗（6–12 个月）记录；投放时间、区域、数量上链。 |
| **RAS 种苗** | 隔离检疫与驯化（如 30 天）、病原 PCR 检测与隔离观察记录；驯化完成后进入分级培育，关键节点上链。 |
| **业务规则** | 种源与投放为可选环节，若配置则与养殖批次关联，溯源链展示时包含种源→投放→养殖路径。 |

### 4.C 养殖/捕捞（双模式）

#### 4.C.1 保水渔业（千岛湖天然有机）

| 项目 | 说明 |
|------|------|
| **登记主体** | 已认证的养殖/捕捞主体；支持按主体筛选「我的批次」。 |
| **必填/选填** | 批次名称/备注、品种（鲢鱼、鳙鱼等）、数量（尾/斤）、捕捞或出塘日期、捕捞/养殖水域（千岛湖 XX 区域）、单位；养殖方式（生态养殖）、捕捞证号。 |
| **水域与生长** | 可选：水域环境数据（浮游生物密度、水温分层、溶解氧等）——物联网或人工录入；自然生长周期（如 2–4 年）与声呐探测/生态评估记录。 |
| **捕捞与净化** | 定置张网捕捞时间与区域；活水运输船暂养；码头吊水净化（7–15 天）记录；关键节点上链。 |
| **业务规则** | 提交后生成**批次号**（平台内唯一）；提交即触发**上链存证**；状态：草稿、已提交（已上链）、已关联下游。 |

#### 4.C.2 RAS 工厂化循环水（引水渔业）

| 项目 | 说明 |
|------|------|
| **登记主体** | 已认证的 RAS 养殖主体。 |
| **水质与设备** | 全封闭水处理参数：pH、氨氮、亚硝酸盐、温度等；传感器/物联网自动采集或人工录入；每立方米水体监测点密度可配置（参考：20+ 监测点）。 |
| **投喂与生长** | 智能投喂与生长监测；基于摄食量与水温的生长曲线预测（可选）；停食净化处理记录。 |
| **生物安保** | 生物安保与疾病预防数据；健康状态 AI 预警记录（可选）。 |
| **出塘与运输** | 低温麻醉与无水保活运输至加工中心；关键节点上链。 |
| **业务规则** | 批次号生成与上链同 4.C.1；支持与种苗引进/驯化环节关联。 |

#### 4.C.3 批次与溯源码（单尾追溯与批次追溯并行）

| 项目 | 说明 |
|------|------|
| **批次号** | 平台统一生成，全局唯一；作为溯源链主键，贯穿加工、储运、销售。 |
| **单尾追溯** | 可选：对单尾鱼赋予唯一编码，与批次关联，实现「单尾追溯」与「批次追溯」并行的编码体系。 |
| **溯源码** | 生成与绑定责任见 **4.E.2**（本平台生成或对接蚂蚁数科流通侧）；与具体批次或子批次绑定；数字码 + 二维码/条形码；消费者扫码即带溯源码查询。 |
| **子批次** | 加工/流通将一批拆成多批时，生成子批次号，与父批次关联，便于流向追踪。 |

#### 4.C.4 鱼种差异化溯源（P2，参考需求文档）

| 项目 | 说明 |
|------|------|
| **鲢鳙** | 见 4.F 认证与标签「鲢鳙差异化」；种质符合 DB3301/T 1139—2024，普通与功能性鲢鳙分级。 |
| **多鱼种扩展** | 墨瑞鳕、三文鱼（大西洋鲑）、斑鳜、鳗鱼等可配置鱼种专属溯源维度与关键品质指标（如原种证明、养殖曲线、功能性成分、口感评级等），后续按品类扩展。 |

### 4.D 加工与检测

#### 4.D.1 加工批次登记（双路径）

| 项目 | 说明 |
|------|------|
| **登记主体** | 已认证的加工企业（含千岛湖智慧鱼谷深加工车间）。 |
| **加工路径** | **传统路径**：活鱼起捕 → 吊水瘦身 → 物理击昏 → 冰鲜保存；**现代路径**：麻醉休眠 → 低温分割 → 气调包装 → 速冻锁鲜。任务/批次可配置路径类型。 |
| **必填/选填** | 加工批次名称/备注、加工类型（分割、冷冻、包装、深加工产品类型等）、加工日期、关联上游批次（单选或多选）、本批产出数量/单位；加工环境监测（温度、湿度、微生物水平）可选录入或物联网对接。 |
| **业务规则** | 关联的上游批次须已上链；提交后生成加工批次号，并**上链存证**；状态：草稿、已提交（已上链）、已关联下游。 |
| **溯源链** | 前端/溯源页展示时，根据「关联上游批次」递归拼接：养殖/捕捞 → 加工 → …。 |

#### 4.D.2 检测报告上传与上链

| 项目 | 说明 |
|------|------|
| **登记主体** | 已认证的检测机构或加工企业（自检）。 |
| **必填字段** | 关联批次（养殖批次或加工批次）、检测类型（如药残、重金属、感官）、检测结论（合格/不合格）、报告文件上传（PDF/图片）、检测日期。 |
| **上链策略** | 报告文件哈希（如 SHA256）上链存证，必要时报告摘要（结论、检测项、日期）一并上链；原文存业务库或对象存储，链上存证用于防篡改。 |
| **展示** | 溯源查询时展示「检测结论 + 报告编号/哈希 + 链上核验结果」；可提供报告原文查看或下载链接（权限可控）。 |
| **不合格处理** | 若结论为不合格，可在监管侧标记预警、限制该批次进入流通或触发复检流程（业务规则可配置）；与蚂蚁数科流通侧协同时，可约定不合格批次不向流通系统推送或由流通侧拦截。 |

### 4.E 流通环节对接与销售/溯源码（流通由蚂蚁数科已建成）

**范围说明**：储运、入库/出库、配送等**流通环节由蚂蚁数科团队已建成**，本平台**不建设**流通登记功能；本平台负责**与蚂蚁数科流通系统对接**及**溯源码与销售绑定的责任边界**（以与蚂蚁数科约定为准）。

#### 4.E.1 与蚂蚁数科流通系统对接

| 项目 | 说明 |
|------|------|
| **对接目标** | 获取储运、入库/出库、流向、销售等流通侧数据，用于溯源链展示（「鱼的一生」含流通节点）与监管报表中的流向查询。 |
| **对接方式** | 以与蚂蚁数科约定为准：如 API 拉取/推送、批量同步、事件订阅等；需约定批次/溯源码等主键与数据格式，保证与本平台种源/养殖/加工/检测环节可关联。 |
| **数据范围** | 流通节点摘要（起运/到达、温控关键点、权责转移等）、入库/出库记录、流向路径、销售记录（若由流通侧提供）；敏感字段按合规脱敏。 |
| **本平台职责** | 对接接口开发、数据映射与落库（或实时查询）、溯源链与报表中展示流通节点；**不建设**流通侧的登记、储运、出入库功能。 |

#### 4.E.2 销售与溯源码绑定（责任边界）

| 项目 | 说明 |
|------|------|
| **责任边界** | 以与蚂蚁数科约定为准，以下为两种常见划分：① **本平台生成溯源码**：在加工/养殖批次流出至流通前，由本平台生成溯源码并绑定批次，将溯源码与批次信息提供给流通侧使用；绑定关系在本平台上链存证。② **流通侧生成溯源码**：流通/销售环节在蚂蚁数科侧完成溯源码生成与绑定，本平台通过对接获取溯源码与批次/销售关联，用于溯源查询时反查。 |
| **本平台能力（若约定为本平台生成）** | 溯源码生成（一物一码/一批一码）、与批次或子批次绑定、绑定关系上链存证；数字码 + 二维码/条形码；批量生成与打印支持；向流通侧提供溯源码及关联批次信息。 |
| **本平台能力（若约定为对接流通侧）** | 接收或拉取流通侧溯源码与批次/销售绑定关系；溯源查询时根据溯源码反查本平台批次并拼接流通节点，展示完整「鱼的一生」。 |
| **状态** | 溯源码：未使用、已绑定、已查询（可选统计）；若由流通侧维护，则以对接数据为准。 |

### 4.G 溯源查询（C 端）

#### 4.G.1 查询入口与展示（「鱼的一生」）

| 项目 | 说明 |
|------|------|
| **入口** | 一键扫码（解析溯源码）或网页/小程序内输入溯源码。 |
| **展示内容** | ① **「鱼的一生」可视化时间轴**：种源/投放（若有）→ 养殖/捕捞（保水或 RAS）→ 加工 → 检测（若有）→ **流通**（储运/入库出库/配送等，**数据来自对接蚂蚁数科流通系统**）→ 销售；② 各节点关键信息（主体名称、时间、品种/数量等脱敏摘要）；③ 有机认证、地理标志、GAP 等证书展示与有效期；④ **生态贡献**（如「本产品鲢鳙鱼已滤食 ×× 吨浮游生物」）；⑤ 检测结论与报告核验入口；⑥ **链上核验结果**：关键节点存证在蚂蚁链上的核验状态。 |
| **增值（P2）** | 基于溯源的烹饪建议与营养分析。 |
| **体验** | 溯源码无效或已注销时提示「无效溯源码」；链上核验失败或超时时可展示「链上核验暂不可用，请稍后再试」，不影响溯源链展示。 |

#### 4.G.2 链上存证核验

| 项目 | 说明 |
|------|------|
| **核验逻辑** | 根据业务库中记录的存证凭证（如蚂蚁链交易哈希），调用蚂蚁链核验接口；展示「链上核验通过」及存证时间，或「核验失败」及原因。 |
| **展示层级** | 可按节点展示（如养殖节点已核验、加工节点已核验）；或整链展示一条「本溯源链关键数据已上链存证并核验通过」。 |
| **防伪** | 链上核验通过可作为「未被篡改」的证明，配合品牌与包装，降低仿冒品冒充风险。 |

## 六、成功指标与验收标准

### 6.1 业务成功指标（参考需求文档）

- **全链路覆盖**：至少覆盖「养殖/捕捞（保水或 RAS）→ 加工 → 检测（若有）→ **流通（对接蚂蚁数科）** → 销售 → 消费者扫码」一条完整链路；本平台环节关键数据上链，流通环节数据通过对接获取并展示；支持单尾追溯与批次追溯并行。
- **双模式**：保水渔业（千岛湖天然有机）与 RAS 工厂化循环水两条溯源路径均可配置与展示。
- **链上可验**：消费者扫码可看到至少 2 个环节的「链上核验通过」展示。
- **认证与公信**：有机认证、地理标志、GAP 等证书可绑定并在扫码页展示，实时更新有效期。
- **监管可用**：政府可查看主体列表、批次列表、检测结果与流向，并可导出报表；与浙食链数据标准兼容。
- **企业价值**（参考需求）：24 小时内问题产品全链定位与召回；减少重复检测与纸质记录目标 70%+；品牌溢价与大型商超/生鲜电商准入支撑。

### 6.2 产品验收标准（首版）

- [ ] 主体管理、蚂蚁链存证/核验对接完成；与浙食链数据标准/赋码规范兼容方案明确。
- [ ] 保水渔业或 RAS 至少一种养殖模式下的养殖/捕捞登记可上链并核验。
- [ ] 加工批次登记（双路径可配置）、检测报告上传与上链完成，与上游批次关联正确。
- [ ] **与蚂蚁数科流通系统对接完成**，溯源链与报表可展示流通节点及流向；**溯源码与销售绑定**按约定由本平台生成并绑定或对接流通侧数据完成。
- [ ] C 端溯源查询页可展示「鱼的一生」时间轴、链上核验结果、认证展示（若有）、生态贡献（若有）；异常提示明确。
- [ ] 监管方可使用批次与流向报表；权限与操作/上链日志可查。
- [ ] 实施路线：试点范围（1–2 家或核心品类）与第一阶段目标明确。

## 七、与蚂蚁链的对接要点（建议）

| 环节 | 建议对接方式 |
|------|--------------|
| **存证** | 使用蚂蚁链 BaaS 提供的存证 API，将种源/投放、养殖/捕捞、加工、检测、溯源码绑定（若在本平台）等**本平台环节**关键数据的哈希或结构化摘要上链；**流通环节**由蚂蚁数科侧建设与存证，本平台不重复存证流通节点。 |
| **核验** | 消费者或监管方溯源时，用业务库中的存证凭证调用蚂蚁链核验 API，返回核验结果与存证时间，前端展示。 |
| **身份与权限** | 主体与链上身份/账户的映射由平台或政府侧在蚂蚁链控制台配置，业务系统只传「主体标识 + 业务数据」，由平台统一发起存证。 |
| **联盟与节点** | 具体联盟成员、节点数量、共识与权限以蚂蚁链产品文档与客户商务为准；本方案预留「链配置」与多链扩展。 |
| **浙食链兼容** | 数据标准、赋码规范与浙食链及未来全国平台兼容；蚂蚁集团为浙食链早期技术承建方，对接时可优先对齐其溯源平台输出能力。 |
| **与蚂蚁数科流通系统对接** | 流通环节由蚂蚁数科已建成；本平台通过约定接口获取储运、入库/出库、流向、销售等数据，用于溯源链展示与监管报表；溯源码生成与绑定责任边界以双方约定为准。 |
