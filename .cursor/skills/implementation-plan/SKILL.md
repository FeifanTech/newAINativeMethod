# 实现计划 / 任务拆解

## 触发条件

- 用户提到：拆任务、实现计划、开发任务、implementation plan、迭代任务、开发计划。
- 用户意图：将需求或技术方案拆解为可执行、可验收的开发任务。

## 原则（与 development-principles 对齐）

- **小步可交付**：每个任务可独立交付、可验证、可回滚。
- **可追溯**：任务与需求/设计可关联（如 issue 编号、文档章节）。
- **验收清晰**：每项任务有明确的验收标准或完成条件。

## 产出结构建议

1. **任务列表**：编号、标题、所属模块/服务、依赖（前置任务）、预估（可选）、验收标准。
2. **建议顺序**：按依赖关系排序，标出可并行项。
3. **风险与阻塞**：若有外部依赖或风险，单独列出。

## 输出要求

- 任务粒度以「1～3 天可完成」为宜，避免过大或过碎。
- 适配多服务/多仓库时，标明任务所属仓库或服务边界。
- 可与 **role-developer**、**development-principles** 串联：拆完后按开发原则做实现与自检。

## 使用说明

- 用户可说「根据这份 PRD/技术方案拆成开发任务」「给我一个实现计划」。
- 开发流程与质量门禁见 `.cursor/skills/development-principles/SKILL.md`。
