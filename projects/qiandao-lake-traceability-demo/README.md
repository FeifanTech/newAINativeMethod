# 千岛湖全鱼品溯源平台 · Demo（第一版）

高保真前端 Demo，依据 [PRD](../../docs/QIANDAO_LAKE_FISHERY_TRACEABILITY_PRD.md) 与 [技术方案](../../docs/QIANDAO_LAKE_TRACEABILITY_TECH_SOLUTION.md) v0.3。**纯前端、无后端**，数据临时存于浏览器 **localStorage**。

## 运行方式

1. 用浏览器直接打开 **`index.html`**（或通过本地静态服务器访问项目根目录）。
2. 无需安装依赖、无需构建。

```bash
# 若使用 Python 启动简单 HTTP 服务（可选）
cd projects/qiandao-lake-traceability-demo
python3 -m http.server 8080
# 浏览器访问 http://localhost:8080
```

## 交互结构（角色 + 向导）

- **首页**：三个角色入口 —— **政府监管**、**企业登记向导**、**消费者溯源**。
- **政府监管**：顶栏子导航（主体管理、养殖批次、加工批次、检测报告、溯源码、监管报表），与原有功能一一对应，统一政务蓝风格。
- **企业登记向导**：步骤条 + 五步向导 —— ① 主体登记 → ② 养殖/捕捞 → ③ 加工批次 → ④ 检测报告 → ⑤ 溯源码绑定；每步可独立进入，上一步/下一步引导闭环。
- **消费者溯源**：单页输入溯源码，展示「鱼的一生」时间轴。

## 功能范围（可点击）

| 入口/页面 | 说明 |
|-----------|------|
| **首页** | 角色入口：政府监管 / 企业登记向导 / 消费者溯源。 |
| **政府监管** | 主体管理、养殖批次、加工批次、检测报告、溯源码、监管报表（统计与批次流向）。 |
| **企业向导** | 五步：主体登记 → 养殖/捕捞 → 加工批次 → 检测报告 → 溯源码绑定；数据存 localStorage。 |
| **消费者溯源** | 输入溯源码 → 「鱼的一生」时间轴：养殖 → 检测 → 加工 → 检测 → 流通（模拟蚂蚁数科）→ 销售。 |

## 数据存储（localStorage）

- 键前缀：`trace_demo_`
- 键：`trace_demo_subjects`、`trace_demo_batches_farming`、`trace_demo_batches_processing`、`trace_demo_inspections`、`trace_demo_trace_codes`
- 清除数据：浏览器开发者工具 → Application → Local Storage → 删除上述键，或清除站点数据。

## 建议使用顺序（验证闭环）

- **企业端**：首页 → 企业登记向导 → 按步骤 ①～⑤ 完成（主体 → 养殖 → 加工 → 检测 → 溯源码），或从顶栏直接进入某一步。
- **消费者**：首页 → 消费者溯源 → 输入已绑定的溯源码 → 查看「鱼的一生」。
- **政府端**：首页 → 政府监管 → 主体管理 / 养殖批次 / 加工批次 / 检测报告 / 溯源码 / 监管报表。

## 说明与限制

- **流通环节**：PRD 约定由蚂蚁数科已建成，本 Demo 在溯源链中以**模拟节点**展示「流通（数据来自对接蚂蚁数科）」。
- **链上核验**：Demo 无真实上链，页面提示「Demo 环境为模拟」。
- **无登录/权限**：Demo 按角色入口组织，政府/企业/消费者入口均可点击，无真实鉴权。
- **无后端**：无持久化、无真实 API，刷新后 localStorage 数据保留，换设备或清缓存即丢失。
